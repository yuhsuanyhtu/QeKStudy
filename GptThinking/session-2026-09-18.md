## 2. Git 能否做前後端 / Can Git support frontend and backend?

### User / 使用者
git 可以做有前端後端的嗎

### Assistant / 助理
Git 本身只負責版本控制，不會執行後端。GitHub 可以儲存前端與後端程式碼，但 GitHub Pages 只能直接託管靜態前端。

完整的零成本前後端架構可由 GitHub 儲存程式碼，前端部署到 Cloudflare Pages 或其他免費平台，後端使用 Cloudflare Workers、Vercel Functions、Supabase 或 Firebase，資料庫則使用 Supabase 或 Firebase。

**English summary:**  
Git is a version-control system, not a backend runtime. GitHub can store both frontend and backend code, while GitHub Pages only directly hosts static frontend content. A full-stack application can still use GitHub as the source repository while deploying frontend and backend components to free hosting/runtime services.

## 11. Agile：一次一個 Story + 每次 Regression / Agile: One Story at a Time + Regression Every Time

### User / 使用者
那我們使用agile方式一次一個來做, 然後每次做regression

### Assistant / 助理
確認 QeKStudy 後續採一次一個 Story 的 Agile 開發方式：

`BDD → SDD → TDD → Implementation → Story Test → Regression → Acceptance → Commit → Next Story`

規則：
- 當前 Story 未完成前，不開始下一個 Story。
- 每個 Story 都必須執行 Regression，不等到大版本才做。
- Regression 失敗時，Story 不算 Done，也不能進入下一個。
- 發現 bug 時，先新增可重現 bug 的 failing test，再修正，再跑完整 Regression。
- 與當前 Story 無關的新想法只進 backlog，不順手實作。
- Story 的 Definition of Done 包括 BDD、SDD、TDD、實作、測試、Regression、驗收、文件與 commit 全部完成。

完整流程已記錄於 `docs/process/AGILE_WORKFLOW.md`。

**English summary:**  
QeKStudy will follow a strict one-story-at-a-time Agile workflow. Every story must complete BDD, design, TDD, implementation, story tests, full regression, acceptance, documentation, and commit before the next story begins. Bugs require a reproducing failing test before the fix, followed by full regression.
